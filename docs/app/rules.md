# Anliegen-Regeln & Website-Autoprofil (FE5 §2–3)

**Rules** — route `/telephony/rules`. Components `src/pages/telephony/_components/rules/*`; data `src/lib/api/owner/rules.ts`; namespace `voice-rules`. Bound to D2 as it ships. The engine's rule is `{id, name, enabled, when:{any_keywords, intent, hours}, then:{action, target, say, fields, priority, stop, alert}, pack}` — there is no pattern in the model at all, so the "no regex for owners" rule holds by construction.

- **List** (`GET /api/voice/rules?profile_id=` → `{rules, effective, conflicts, packs, max_rules}`, 30 s): ordered by priority, highest first (the engine evaluates strongest first); ↑/↓ writes priorities (`POST …/reorder {profile_id, priorities}`, top row highest, optimistic), name, "Wörter: …", action chip, hours chip, enabled switch (`PATCH …/{id} {profile_id, enabled}`), pack badge. Conflicts come from the engine (`{keyword, rules, actions, ambiguous}`): same priority is flagged as "please change the order". Hit counts are an ask.
- **Editor**: keyword chips (fuzzy matching is the engine's default), conditions (opening hours inside/outside, caller intent), one of D2's seven actions — handoff (target from the profile's numbers), route (to an intent), message (fields), answer_from (a source id), ask_callback, end_politely, say — an urgent owner alert, and "Sag es so" (`then.say`, per language). The id is a slug of the name (`slugifyRuleId`). `POST …/rules {profile_id, rule}` upserts; the engine's 422 sentence is shown verbatim (there is no separate validate route).
- **Probelauf** (`POST …/rules/test {profile_id, text, intent, is_open, language}`, one request per line, up to ten): match → rule highlighted, action, the spoken sentence, other matching rules; fallthrough → "Keine Regel — …". An "außerhalb der Öffnungszeiten" switch sets `is_open`. The backend engine decides; nothing is matched client-side.
- **Vorlagen** (`GET …/rules/packs?language=`): preview → "Hinzufügen (deaktiviert)" (`POST …/rules/packs/{id}`, then each installed rule is switched off) → the owner enables each rule.

**Autoprofil** — route `/telephony/settings/profile/autoprofile`; banner on the profile editor ("Wir haben n Angaben auf Ihrer Website gefunden — prüfen"). Data `src/lib/api/owner/autoprofile.ts`. `POST /api/voice/autoprofile {profile_id, url?}` starts a job (a URL means "read this site first"), `GET …/autoprofile?profile_id=` is polled every 3 s while it runs and returns `{job, draft_id, created_at, warnings, fields:[{field, current, proposed, confidence, evidence, note}]}`, `POST …/apply {profile_id, draft_id, fields}`. Review table: field · current · proposed (with the extractor's note) · confidence and evidence count; per-field Übernehmen (marks) / Verwerfen; "Alle vorgemerkten übernehmen (n)" sends **only the marked, usable fields** (`applyPayload`, tested). Nothing is applied without a click; the result is a new profile version by `autoprofile` with the note "Website-Vorschlag übernommen: …" that the owner activates in the editor.
