# Team & Rollen, Auth Phase 2 (FE9 §1)

Route `/telephony/settings/team`. Components `src/pages/telephony/_components/settings/team/*` (`TeamView` with `RoleSelect`, `TenantSwitcher` in the user menu, `ImpersonationBanner`, `SessionSync`); data `src/lib/api/owner/team.ts`; store `src/stores/session.ts`; namespace `voice-team`. Bound to C3 as shipped.

- **Session** — `POST /api/auth/session` is tried first (ask); today `GET /api/status.tenancy {enabled, tenant_id, role, impersonated}` fills `tenantId`, `role`, `impersonating` (`useSyncSession`, mounted once in the shell). Wire roles `owner | admin | viewer` map to the app's `owner | admin | staff` (`roleFromWire`). Single-tenant instances stay `owner` and the team page says so with a C3 badge. Every request carries `X-Pincer-Tenant` (what C3 reads for audited instance-admin impersonation) and `X-Tenant-Id` (the FE spec's belt-and-braces) whenever a tenant is set.
- **Roles** — `can()` matrix (tested): staff = start call, handle attention, add knowledge, read reports; owner = everything incl. reveal, settings, team, erasure, campaign start; admin = owner + the "Im Auftrag von" banner. Nav items carry `action` and disappear for roles that may not (settings submenu, team); the server enforces regardless.
- **Tenant switcher** — visible only when `GET /api/tenants` answers (instance admins). Switching calls `switchTenant()`: cancels and clears the whole query cache, sets the tenant in the store and the header module, and the layout re-mounts on the tenant key (FE9 §1.1 MUST; tested + e2e: no data of the previous tenant remains).
- **Members** — `GET /api/tenants/{id}` → members (`user_id`, `role`) and tokens. Role change = C3's `POST …/members {user_id, role}` upsert; remove = `DELETE …/members/{user_id}`. The last owner cannot be demoted or removed (`isLastOwner`, mirrored in the UI, tested). E-mail invites (`POST …/invites`) and `last_active` are asks; until then members are added by user id.
- **Zugänge** — `POST …/tokens {role, label}` returns the plaintext once; shown through the same `SecretOnce` state machine as webhooks, then gone from the DOM; `DELETE …/tokens/{id}` revokes.
